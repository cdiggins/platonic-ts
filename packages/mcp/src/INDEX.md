# packages/mcp/src

Implements the MCP server (BL-0026): a JSON-RPC-over-stdio process that exposes the code
index as 33 tools — outlines, declarations, type-checked references, inferred types,
diagnostics, dependency analyses, name-addressed editing, move/rename/signature
transformations, checkpoint and revert, and the repository's own check gate. Every write
tool computes an `EditPlan` before touching disk, so it can be previewed, combined with
others into one all-or-nothing batch, or declined outright when a change cannot be made
safely.

| File | Purpose |
|---|---|
| `batch.ts` | Combines several `EditPlan`s into one: fails loudly listing every failed plan rather than the first, and refuses the whole batch if any two plans' edits overlap, so `batch_edit` is genuinely all-or-nothing. |
| `checkpoint.ts` | Snapshots (label, timestamp, full file contents) for `checkpoint`/`revert`: builds a plan to restore changed files to a snapshot, declining the whole restore rather than half-completing it when a file was created or deleted since. |
| `compiler.ts` | Binds a `Workspace`'s texts into a TypeScript `LanguageService` and `Program` (a `Compiler`), and converts the compiler's own `FileTextChanges` into this package's `FileEdit` format — the seam every tool that needs inferred types, diagnostics, or compiler-computed edits goes through. |
| `declaration.ts` | Locates the exact source range of one declaration, including its leading doc comment (stopping at a blank line), and widens a single-declarator variable statement to include its `export` keyword; also checks a source string for syntax errors before it is written into a plan. |
| `diagnostics.ts` | The compiler's own opinion of named files: type/syntax errors, the quick fixes it offers for them, and import organizing. Explicitly a fast, files-scoped inner-loop check — never the gate — and every answer says so. |
| `dispatch.ts` | Routes one parsed tool call to its answer: reads args, decides whether the tool is a read (`query`/`types`/`reach`/`graph`/etc.) or a plan-producing write, loads only the `Workspace` or `Compiler` the branch actually needs, and applies or previews the resulting plan. |
| `edit.ts` | The edit-plan vocabulary shared by every write tool: `FileEdit` (a byte-range replacement), `EditPlan`, overlap detection between edits (the check that prevents back-to-front application from silently corrupting a file), and the two symbol-addressed primitives `replaceSymbol`/`insertSymbol`. |
| `graph.ts` | Structure between declarations and files: `implementations` (heritage clauses and same-name overrides), `moduleGraph` (relative-import edges and every elementary import cycle), and `unusedExports` (exports referenced only within their own file) — each documents the specific blind spot its answer has. |
| `index.ts` | Barrel for the MCP server's pure surface: one level of re-export (PS-023) over every module in this package except the protocol-facing `server.ts`/`main.ts`. |
| `inspect.ts` | Two measurement tools sharing the same counters the rest of the repo uses: `symbolMetrics` (size/complexity of one declaration against its file) and `escapeHatchIndex` (every `any`/`as`/non-null/suppression comment, compared to the ratchet baseline). |
| `io.ts` | The IO edge: holds one repository's index and parsed sources open between calls, rebuilds only what a timestamp scan or file watcher reports changed, and writes an `EditPlan` to disk after re-reading each file to detect that it moved underneath the plan. |
| `main.ts` | Entry point (`npx tsx packages/mcp/src/main.ts`) — resolves the repo root and starts `serve` on stdin/stdout, keeping the protocol on stdout and everything else on stderr. |
| `move.ts` | Moving code between files: `renameFile` rewrites every import specifier pointing at a moved module, and `moveSymbol` relocates one declaration, deciding what it needs in its new home, what its old file no longer needs, and refusing on a hidden dependency, re-export, name collision, or a move that would create an import cycle. |
| `options.ts` | `CallOptions` — the repo directory, ratchet baseline path, and current time every tool call is given besides its own arguments; the clock is a value here rather than something a tool may read (PS-045). |
| `plan.ts` | Maps each write-tool name to the `EditPlan` it produces, without writing anything — the shared step both a direct tool call and one `batch_edit` step go through, so a batched call computes its plan exactly as a standalone call would. |
| `preview.ts` | Renders an `EditPlan` as a unified diff before it runs: a from-scratch longest-common-subsequence line differ (no runtime dependency), plus `previewPlan`, which turns a plan into per-file diff text instead of applying it. |
| `protocol.ts` | JSON-RPC 2.0 framing over newline-delimited JSON, written by hand rather than from an SDK: parses one line into a request or a reportable error, and builds success/error response values. Pure — text in, values out. |
| `query.ts` | The read-only tools that return finished, dense text for an agent to read directly: `outline`, `symbolSource`, `usages`, `search`, and `repoMap` (folder summary plus most-used exports, budget-capped). |
| `reach.ts` | What sits above a declaration: `callers` (a depth-limited, recursion-marked call tree, built by walking each reference up to its nearest enclosing function), `testsForSymbol` (tests that reach it directly or through one level of test-only helper), and `blastRadius` (both plus raw uses in one call). |
| `refactor.ts` | Exposes the compiler's own refactorings (rename-inferable-from-usage, extract, etc.) addressed by declaration name instead of character offset: `availableRefactors` lists what applies, `applyRefactor` runs a named refactor-and-action pair. |
| `rename.ts` | Type-checker-accurate rename: rewrites every resolved reference to a symbol, and declines the whole rename rather than doing it partially when an occurrence is a shorthand property or an aliased import/export specifier that cannot be rewritten by substitution. |
| `review.ts` | Reviewing rather than making a change: `deleteSymbol` removes a declaration only when nothing outside its own range still uses it and no barrel re-exports it; `symbolDiff` reports what changed against a prior snapshot by declaration (added/removed/changed/moved) instead of by line. |
| `schema.ts` | The vocabulary the tool catalogue is written in (`ToolSpec`, property builders like `text`/`flag`/`count`) and the typed readers (`readText`, `readFlag`, `readTextList`, …) that pull a call's arguments back out of the untyped JSON-RPC params. |
| `server.ts` | Composes the tools onto the wire: turns one JSON-RPC request into one response line, catching a tool that throws and reporting it as tool output rather than a protocol error; processes requests in arrival order so two plans computed against the same workspace can never apply out of order. |
| `signature.ts` | Changes a function's parameter list and rewrites every call site to match, using a caller-supplied argument mapping (`$0`, `$1`, … or literal text) rather than inferring one; checks every call site is rewritable before emitting any edit, so a signature change can never land at some sites and not others. |
| `tools.ts` | Assembles the full tool catalogue (`toolSpecs`) advertised to a client, in the order a caller meets the tools — find, ask the compiler, analyse, change, undo — plus the `check` gate tool itself. |
| `toolsRead.ts` | Catalogue entries (name, description, schema) for the read-only tools, grouped as navigation, type inspection, and analysis; each description states what the tool replaces, what it costs, and what it cannot see. |
| `toolsWrite.ts` | Catalogue entries for the tools that change files, grouped as single-declaration editing, larger transformations, and batching/reverting; every entry takes `preview` and its description names the specific cases the tool refuses rather than guesses on. |
| `types.ts` | What the type checker knows about a declaration, printed without truncation: `typeOf` (inferred type plus call/construct signatures, refusing to report an unresolved `any`) and `membersOf` (the full member surface of a type, inherited members attributed to the type they come from). |
| `workspace.ts` | The `Workspace` type (a `CodeIndex` plus its parsed source files) and symbol lookup: resolves a name (optionally scoped to a file) to a unique declaration or explains why it could not — not found, ambiguous, or in a file that is not indexed — plus small position/line helpers every tool builds on. |
